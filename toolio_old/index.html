SCHOOL

[ the learning layer for every agent ]

School is the learning layer behind an agent — coding, research, ops, support. It learns what worked, what broke, and what your project already decided, then hands it back before the next task starts.

01

The window filled up

A transcript grows until it no longer fits the window. School counts the tokens, cuts the oldest messages into named blocks, and keeps the originals. No model is asked, and nothing is thrown away.

    The context engine, as five calls

    Every one of them ships over the MCP server, the CLI and the OpenCode plugin — part of the same fifty-two.

    • context_compressmcp

      Compress the session now, on demand. Returns the blocks added, the tokens before and after, and the trigger that fired.

      use when the window is close to full
    • context_restoremcp

      Restore one block, or every block. Gives the original messages back for a block id, and reports what it reopened.

      use when the agent needs the old detail
    • context_statusmcp

      What the engine is holding right now: blocks stored, restores served, tokens saved and the view mode in force.

      use when you want the numbers
    • context_viewmcp

      Builds the layered view the agent is actually given, with the token ratio and the segments it will see.

      use when you want to see the view
    • context_coexistmcp

      Decides who owns the context window — School, another compressor, or both — and lets you switch without a restart.

      use when something else is compressing too

    02

    One request, five hops

    A tool call becomes one line of JSON on a pipe. The engine answers on the same pipe. No server runs, no account exists, nothing leaves the machine.

    1. 01agentopencode
    2. 02pluginschool.ts
    3. 03bridgestdin → stdout
    4. 04enginev2.6
    5. 05store.school/memory
    1. 01

      The agent asks

      One of 52 typed tools, with a schema the model already knows.

      school_remember({ content: "…" })
    2. 02

      The plugin translates

      Arguments become a JSON request. The plugin never talks to a network — it owns one child process.

      { "command": "remember", "worktree": "…" }
    3. 03

      The bridge carries it

      One process per call, one line in, one line out. If it dies, the tool fails loudly instead of lying.

      python scripts/school_bridge.py < request.json
    4. 04

      The engine decides

      Dedupe, conflict detection, confidence scoring and scope checks happen before anything is written.

      MemoryManager.store_experience(...)
    5. 05

      The store persists

      One file per project, one namespace per session. Another project can never read it.

      .school/memory/v26_memory.json

    03

    What a block actually holds

    Forty-eight cells, three blocks, one honest accounting: what went in, what it costs now, and how to get the original back.

    1. b1messages 0 → 4

      Four messages, one summary, both stored. The summary is what the model sees; the range is what you can restore.

    2. b3messages 8 → 12

      Blocks stay independent. Restoring one never rewrites the others, so a compression can always be undone.

    3. b7messages 24 → 31

      Layer 0 blocks are deterministic: no model wrote them, so they cost nothing to regenerate and nothing to doubt.

    04

    Fifty-two tools

    Not fifty-two commands you have to remember. Six folders, one per area. Open a folder and the tools are inside it.

    05

    Install it from the source

    Nothing is published yet — no PyPI package, no Homebrew tap, no Chocolatey package, no npm package, no built installer. The five steps below are the whole install, in order, and each one actually runs.

    1 · clone
    $ git clone https://github.com/dex34132-web/A-School-For-AI.git

    This is not a coding-agent tool. It runs behind any agent that speaks MCP or loads a plugin · github.com/dex34132-web/A-School-For-AI

    06

    Measured, not asserted

    Three views of the same repository, counted from it: every commit, every test file, every source file. Nothing here is a benchmark, and nothing here is about your results.

    07

    Any agent that speaks MCP

    Claude Code, Codex, Cursor, Windsurf, Cline, Roo Code, Gemini CLI, Goose, Aider, Continue, Copilot Chat — or anything else that speaks the Model Context Protocol. One server, one memory, the same 52 tools, with a budgeted resource set instead of a firehose.

    
      
    school mcp config <client> prints the block for that client. The same server answers every one of them.
