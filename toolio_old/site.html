[ the learning layer for every agent ]

AI Agents, But Better and they learn.

School is the learning layer behind an agent — coding, research, ops, support, anything that runs on a loop. It records what worked, what broke and what was already decided, then hands the lesson back before the next task starts. No cloud, no training, no fine-tuning: a local engine that gets better at your project, with everything kept in .school/memory/.

01

The window filled up

A transcript grows until it no longer fits. School does not forget it, and it does not ask a model. It counts, it compresses, and it keeps the originals.

session · teach · 14:02
    context window0 / 128k
    CONTEXT TRUNCATED12 messages → 1 block · originals kept
    1. 01

      The meter watches every message

      Tokens are counted as each message lands. Nothing disappears silently — every compression is visible, with the number that caused it.

    2. 02

      A deterministic trigger fires

      At 92% of the window the engine starts compressing. No model call, no network, no waiting — it is a pure function of the messages already in hand.

    3. 03

      Messages become blocks

      A block stores the exact message range, a summary, and the token cost of both. The original messages are never mutated — they are still on disk, byte for byte.

    4. 04

      The session carries on

      The window reopens. When the agent needs the old detail it asks for the block and gets the original messages back, not a paraphrase of them.

    02

    One request, four hops

    A tool call becomes one line of JSON on a pipe. The engine answers on the same pipe. No server runs, no account exists, nothing leaves the machine.

    1. 01agentopencode
    2. 02pluginschool.ts
    3. 03bridgestdin → stdout
    4. 04enginev2.6
    5. 05store.school/memory
    1. 01

      The agent asks

      One of 52 typed tools, with a schema the model already knows.

      school_remember({ content: "…" })
    2. 02

      The plugin translates

      Arguments become a JSON request. The plugin never talks to a network — it owns one child process.

      { "command": "remember", "worktree": "…" }
    3. 03

      The bridge carries it

      One process per call, one line in, one line out. If it dies, the tool fails loudly instead of lying.

      python scripts/school_bridge.py < request.json
    4. 04

      The engine decides

      Dedupe, conflict detection, confidence scoring and scope checks happen before anything is written.

      MemoryManager.store_experience(...)
    5. 05

      The store persists

      One file per project, one namespace per session. Another project can never read it.

      .school/memory/v26_memory.json
    ╭─┄ ──╭
    03

    What a block actually holds

    Forty-eight cells, three blocks, one honest accounting: what went in, what it costs now, and how to get the original back.

    1. b1messages 0 → 4

      Four messages, one summary, both stored. The summary is what the model sees; the range is what you can restore.

    2. b3messages 8 → 12

      Blocks stay independent. Restoring one never rewrites the others, so a compression can always be undone.

    3. b7messages 24 → 31

      Layer 0 blocks are deterministic: no model wrote them, so they cost nothing to regenerate and nothing to doubt.
